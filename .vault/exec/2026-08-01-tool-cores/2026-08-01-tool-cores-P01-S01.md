# Split the registry trust-root marker so network egress is its own declared axis: an entry or native tool set with no egress declaration is REFUSED fail-loud at the real composition seam, never defaulted, migrating the sole existing registry entry to declare no-egress in the same change so the tree stays green. Closes on a test that drives the production config-home and spawn composition path and proves the refusal fires for an undeclared entry (executor-core)

## Scope

- `src/vaultspec_a2a/providers/_acp_mcp.py`

## Description

- Split the registry trust root into two independent declared axes, leaving the
  local-write axis with its exact prior failure mode and adding network egress
  beside it, neither inferred from the other.
- Introduce a registry construction seam that refuses any entry omitting either
  axis or declaring one non-boolean, and route the shipped registry through it,
  so an undeclared entry is unconstructible rather than merely unsurfaceable.
- Add an egress assertion mirroring the existing read-only one, hold both behind
  a single trust-root assertion, and swap that in at the two existing call sites
  so the failure mode and the sites are unchanged.
- Migrate the sole existing registry entry to declare no egress in the same
  change, keeping the tree green.
- Carry the same axis onto the native tool set, where membership is the
  declaration, and refuse undeclared names at the spawn composition path.
- Add an optional extra-names parameter to the native composition function with
  a default that is byte-identical to prior behaviour, as the production
  extension point the next Step needs.

## Outcome

Landed as `e86d8d54`. Both axes are declared, and the capability stays dark: no
web tool name reaches any allowlist in this Step.

The firing proof is split, deliberately, and one half is stronger than the row
anticipated. The native tool axis is a true wiring proof - the refusal fires at
the real spawn composition seam, driven by the exact call the worker node makes
against a real chat model, with a genuinely undeclared name arriving as caller
data. The registry entry axis refuses at the production constructor rather than
at composition, which makes an undeclared entry impossible to construct at all.

Gates: lint and format clean on the changed files; whole-tree type check clean
in this module; the providers and graph suites at 665 passed with three failures
attributed by evidence to another session's uncommitted profile work, none of
which reaches this module.

## Notes

An honest limit, recorded rather than buried, and it generalizes beyond this
Step. Removing the egress assertion from the composition seam breaks no test,
because the registry is closed by design: no production input can present an
undeclared entry there. Making it fire would require monkeypatching the registry
or adding an injection parameter with no production caller, both forbidden here.
The guard was kept as the belt to the constructor's braces, and the constructor
is the half that genuinely cannot be evaded.

The finding that matters is the generalization: the pre-existing read-only
assertion has exactly the same property. Deleting it also breaks nothing. This
module has therefore carried an unprovable fail-loud guard since before this
Step - documentation rather than enforcement - and nobody had noticed. Recorded
in the feature's rolling audit as a finding in its own right rather than left to
be rediscovered.

Three calls were judged rather than followed and all were ratified. The extra
names parameter is a production extension point with a named future consumer,
not a test seam; removing it would cost this Step its only real input and force
the next Step to reinvent the same seam. Egress validation runs before the
autonomy and role gates, so an undeclared tool set is refused on every run rather
than first surfacing on a document role in production having passed every
supervised run before it. And the axis is expressive rather than prohibitive: an
entry may declare egress and still compose, since the governing record requires
visibility rather than a ban, and its consequence clause fails loud on a missing
declaration, not a present one.

Handoff for the delivery Step: the two web built-in names must be declared on
the native egress map or composition will refuse them, and they compose through
the extra names parameter added here.
