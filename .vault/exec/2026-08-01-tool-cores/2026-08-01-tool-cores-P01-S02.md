# Admit the typed web locator into the research-finding contract - kind web, url, retrieved-at ISO-8601, optional title and capped excerpt - enforced in the branch-side finding validation with caps. Closes on a graph-level test through the real dispatch, reducer, and checkpoint seam proving the locator survives into checkpointed state and reaches synthesis, never a direct field-set (executor-core)

## Scope

- `src/vaultspec_a2a/graph/nodes/diverge.py`

## Description

- Admit a locator entry as either a bare string, which preserves internal
  locator behaviour unchanged, or a dictionary declaring its kind.
- Define the web kind with required kind, url, and retrieved-at fields and
  optional title and excerpt, and hang validation off the existing branch-side
  finding validator so it fires on the real branch path rather than a new one.
- Cap the excerpt, the field lengths, and the number of web locators per
  finding, refusing rather than truncating on breach.
- Restrict the URL scheme to the two web schemes.
- Refuse unknown keys on a web locator.
- Export the kind constant and the caps so downstream consumers select by the
  shared constant rather than by a literal.

## Outcome

Landed as `8e0d68d8`. The reducer needed no change: the finding is untyped where
it is declared, and the only place its shape is enforced is the branch-side
validator, so the contract landed entirely within scope.

Acceptance is the checkpoint round-trip and it was made to bite. The test never
sets the finding list directly. Locators are produced inside branches, fan in
through the real reducer, are observed at the synthesis join, and are read back
through a second checkpoint saver opened on the same file after the first
connection closed, with the graph recompiled.

The harness was itself probed rather than trusted: the serializer genuinely
rejects an unserialisable shape, so the boundary is real; and reading back under
a different thread identifier, or after deleting the backing file, both return
empty, so the assertion can fail. An on-disk saver was chosen over the module's
existing in-memory one deliberately, because in-memory would not have proven
serialisation - the half of surviving into checkpointed state that can actually
be dead.

Gates: lint and format clean; whole-tree type check clean in this module; graph
and thread suites at 392 passed; the wider suite carrying two environmental
discovery failures attributed by socket probe to a live engine on the
development host, which this module has no path to.

## Notes

Six calls were judged rather than followed; all were ratified.

Caps refuse rather than truncate. The record says enforced with caps without
specifying, and every other cap in the tree fails loud. Only the producer knows
which part of a retrieval carries the evidence, so a validator silently
discarding the tail of a cited excerpt would be precisely the quiet degradation
this campaign exists to close. The consequence is real and accepted: a producer
emitting an oversized excerpt kills the branch rather than being trimmed.

The URL scheme restriction is an addition the record implies but does not state,
flagged as such rather than smuggled in. A local-file or script-scheme locator
would otherwise ride the channel into a sources section disclosed verbatim to a
reader, which is the exact axis the sibling Step exists to model.

The count cap is tied to the delivery Step's per-branch fetch budget, so a
branch cannot cite more retrievals than it is permitted to make. The
retrieved-at field admits a bare date as well as a full instant, because a bare
date is the granularity the record's own sources section cites at, and requiring
an instant would have refused the disclosure form the record asks for.

One coordination item surfaced and was resolved outside this Step: the consuming
Step had independently declared its own copy of the kind constant. Exporting the
constant here caught that duplicate on the day the contract was born, and the
consumer now imports it.
