# Extend the submit refusal structurally: when accumulated findings carry web locators, every distinct locator URL must appear in the proposed document body, else the document-conformance error routes the run into the existing revision loop. Closes on a test through the real submit path proving the refusal FIRES on an undisclosed URL, plus a mutation run demonstrating the test fails when the check is absent (executor-core)

## Description

- Read the distinct web locator URLs out of the accumulated findings in
  first-seen order, deduplicated, skipping malformed entries.
- Extend the existing conformance-note composition with one note per undisclosed
  URL, alongside the notes already produced, so the refusal reuses the existing
  error and the existing revision-loop routing rather than adding a second
  mechanism.
- Scan the prose region only, so a URL placed in frontmatter cannot discharge
  the obligation.
- Scope the check to research documents.
- Read the locator kind from the shared contract constant rather than a local
  literal.

## Outcome

Landed across three commits: the refusal, then the research scoping, then the
shared-constant import. The final state is `13034e18`.

The mutation evidence is the substance of this record. Three mutations were
applied, observed, and reverted. Deleting the predicate fails the real-submit
tests. Cutting the wiring while leaving the predicate intact fails everything
except the test that calls the note composition directly, which is the correct
signature for a wiring-only mutation. Removing the scope guard fails the
non-research cases while the research case correctly keeps passing - the
signature of a scope-only mutation, and the reason the two are paired: one
document type refuses on exactly the state the other accepts, so the guard is a
real axis rather than a disabled check.

One mutation result is worth more than its pass count. With the predicate
absent, the primary test fails on a connection error after a second, rather than
on an assertion, because the submitter is pointed at a closed port. That failure
proves ordering - the refusal precedes any engine contact - which an assertion
failure alone would not have shown.

Gates: lint and format clean on the changed files; whole-tree type check with
zero diagnostics in this module; the authoring, thread, and graph suites at 553
passed, carrying the same two environmental discovery failures attributed by
socket probe to a live engine on the development host.

## Notes

The scoping to research documents was a correction applied mid-Step, and the
reasoning recorded in the code is deliberately not the one first noticed. The
observable symptom was that the decision record's wording carries no phase
qualifier while the finding list persists across phases in one run, so an
architecture record in a web-grounded run would also have had to disclose every
URL - and the architecture template carries no sources section, the research
template being the only one in the tree that does.

The deciding reason is the vault's own document boundary rather than that gap:
each fact has one home, the research document grounds and every later document
cites it by stem without restating its evidence. A URL is evidence. Demanding
URLs in a later document would satisfy one rule by breaking another. The
executor implemented the rule as recorded and flagged the consequence rather
than narrowing a recorded decision unilaterally, which is the correct order.

Where enforcement now ends, recorded rather than fixed: non-research documents
are machine-unchecked for web evidence and rely on the research stem in their
related field carrying the URLs. The decision record's reviewer-persona and
human-gate obligations are the only backstop there. That is correct under the
boundary, but it is a real edge and should not be rediscovered later as a gap.

Two smaller calls stand as implemented. Matching is exact substring rather than
normalized, so a reformatted URL is refused; this is deterministic and
replay-exact by design, and softening it would create a second, weaker contract.
The prose-region-only scan is deliberate, on the reasoning that a URL smuggled
into the frontmatter would discharge one obligation by committing a different
violation.

The shared-constant import closed a duplicate declaration of the kind literal
that had been introduced here before the contract Step exported it. Import
order was probed in both directions and the two names resolve to one object,
confirming a single owner; the module involved reaches nothing in this package,
so no cycle exists. The test fixture was additionally wired through the imported
constant, so a future rename of the kind fails the tests rather than silently
ceasing to fire - an equality assertion between the two would have been
tautological once there was one constant, but wiring the fixture through it is
not.
