# Introduce the proven-web-lanes activation gate consumed by both tool composition and persona-text composition, empty at landing, by EXTENDING the existing lane-admission module rather than declaring a second mechanism

## Description

- Extend the existing lane-admission module with a web-proof declaration rather
  than introducing a second registry, after semantic grounding found the
  completed-turn mechanism already implemented the exact pattern this Step
  required.
- Declare web proof as a SIBLING mapping rather than a field on the existing
  proof record.
- Export a predicate as the seam every consumer binds to, so no consumer depends
  on the declaration's shape.
- Add an invariant that web proof implies turn proof.
- Land the module and its test, which had been left untracked by another
  session, and fix the helper-signature defect that made the test fail.

## Outcome

The gate exists, is empty at landing, and the capability is dark: the web
declaration is a frozen empty mapping, and no web tool name reaches any
production path. Verified after the fact rather than on report, because the
executing agent terminated before delivering one.

The sibling-versus-field decision is recorded in the module itself and its
reasoning holds independently of who made it. The two proofs are earned and
withdrawn independently - upstream tool drift can cost a lane its web
activation while it keeps serving turns perfectly - so folding them into one
record would make withdrawing one an edit to the other's citation. The turn side
also admits lanes through two declarations rather than one, which a shared field
could not express.

The predicate seam was decided at coordination level rather than by this Step,
at another executor's request: it asked for a function rather than a data shape
so it could bind immediately and stay immune to whichever declaration form
landed. That request was right and became the phase-wide convention.

## Notes

This Step exists in its final form only because of a semantic dedup sweep before
dispatch. As originally written it would have declared a parallel proven-lanes
mechanism beside one that already existed, whose own docstring argues the same
reasoning this plan does - deny by default, hand-edited, each entry citing the
live test that earned it, never derived by scanning, because a derived set
silently re-admits a lane the moment an unrelated test appears. Four agents had
spent the day attributing test failures to that module without reading it. One
search by meaning surfaced it; keyword search would not have, because the
identifiers mask in this repository.

The Step was blocked mid-flight on the module being untracked while a sibling
already imported it, and unblocked by landing it here rather than waiting.

A merge of a feature branch concluded underneath this Step. Its work survived
intact, unlike some incoming symbols elsewhere in the tree.

No Step Record exists in the executor's own words: the agent terminated before
reporting. Everything above is verified from the committed tree - the
declaration is empty, the predicate is exported, the test suite passes, and the
capability is dark - rather than taken from a report that was never delivered.
