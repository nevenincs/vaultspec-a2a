# Compose the Claude and Z.ai web built-ins WebSearch and WebFetch into the autonomous allowlist by exact name for every document-authoring role, using the same role predicate that governs the native read floor, gated on the proven set, carrying the decided bounds through the first-party controls

## Description

- Declare the two command-line web tools in the native egress map, so the trust
  axis refuses them unless their outward reach is stated.
- Compose them onto the native read floor through the extension point an earlier
  Step in this Phase provided, using the same role predicate.
- Carry the decided per-branch use caps, content-token cap, and domain posture
  through the provider's own first-party controls rather than reimplementing
  them.
- Gate composition on the web-proof predicate.
- Remove the web-search registry entry and its desktop-capability action.

## Outcome

The command-line lanes compose their own web tools behind the gate, and the
capability is dark: the proven declaration is empty, so no lane surfaces a web
tool name today.

The registry entry removal is the substantive half of this Step and was not in
its original scope. A registry member naming a first-party web-search server had
arrived on a concurrent line and been restored after a merge lost it. No such
server exists or is planned; it wrapped a third-party package under a
first-party name. It is withdrawn, and the registry now carries a single
no-egress member plus a comment recording why no web entry belongs there.

That withdrawal reddened thirteen tests, which was the correct consequence and
not a regression. Several proved the fiction and were removed. Several others
proved the egress axis itself and merely used the entry as their fixture; those
were retargeted onto the native tool path, which is a better subject because it
is what actually ships rather than an exemplar kept alive to be tested. No
test-only registry member was introduced to substitute for it, deliberately.

## Notes

The removal was directed mid-Step and landed before the retarget, which was the
wrong order. A concurrent reconciliation had recorded that the entry was the
egress mechanism's only egressing exemplar and that withdrawal must retarget
that coverage rather than delete it; the removal went first anyway and broke the
coverage before the replacement existed. The end state is right and the sequence
was not. Recorded because the same hazard recurs whenever a fixture and the
mechanism it proves are withdrawn in one motion.

The executing agent reached its session limit mid-flight, so this record is
written from the committed tree and the passing acceptance suite rather than
from its report. The bounds and the composition seam are verified present; what
is not verified in the executor's own words is why each bound carries the value
it does, beyond the decision record's own numbers.
