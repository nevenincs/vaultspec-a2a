# Prove the Codex live-mode lane live to the completed-retrieval standard, additionally verifying the undocumented axis the decision record constrains - live web search actually surfacing and invoking under the read-only sandbox and never approval policy

## Description

- Drive a real turn on the lane under the served live posture and require it to
  return a value the model could not have recalled.
- Drive the same prompt under the disabled posture as the control.
- Prove the production research chain lands a typed web locator.
- Admit the lane to the web-proven declaration, citing the test by node id.

## Outcome

The lane is proven and admitted. Six checks pass end to end against the real
installed binary under real session authentication, taking roughly three minutes
because the retrievals are real.

The test design is what makes the proof mean something. It is differential
rather than positive: the live posture must return a value only a live index
could supply, and the SAME prompt under the disabled posture must perform no
search at all. A positive-only assertion would have been satisfied by a model
recalling something plausible from training, which is precisely the failure a
retrieval proof exists to exclude. The control is the evidence; the passing run
alone is not.

The cheap probe this Step was forbidden to use stayed unused. Delivery work had
established by running the binary that debug prompt-input output is byte
identical across all four postures, because search is server-side and never
reaches the model-visible prompt input. Recording that in the row beforehand
saved this Step from spending its budget on an assertion that could not have
worked.

## Notes

The proof is flaky under load and that is a real property rather than an
incident. Run inside a batch alongside five siblings it failed once; run alone
it passed twice, and the full file passed cleanly afterwards. The failure was
contention, not a broken assertion. A live retrieval proof depends on an
external service responding within a turn's patience, so it will fail sometimes
for reasons that have nothing to do with the code it guards. Anyone reading a
red run here should re-run it alone before treating it as a regression.

That flakiness bears on how the admission should be read. The declaration is a
record that a lane DEMONSTRATED a completed retrieval, not a promise that the
demonstration reproduces on demand. Nothing about the mechanism assumes the
proof is deterministic, and it should not be rewritten to make it so - a proof
made deterministic by removing its dependence on the live service would stop
proving the thing it exists to prove.

The lane's declaration carries no tool names, deliberately, and the entry says
so: this lane's web reach is configured through its per-run posture rather than
composed as allowlisted built-ins, so an empty tool tuple is the honest shape
rather than an omission.

The executing agent reached its session limit before reporting, so this record
is written from the committed tree and from running the proof directly three
times. What is not captured in its own words is why it chose the differential
shape - though the shape speaks for itself.
